# Worldglance — IB CAS Creativity

Worldglance is also being developed as an IB CAS Creativity experience.

CAS is secondary to the product-development process. Development should not be distorted simply to produce CAS paperwork.

The goal is to document genuine work that is already happening.

## Creativity connection

Worldglance involves creative work through:

- product design
- visual design
- programming
- 3D graphics
- UI/UX design
- technical problem solving
- experimentation
- iteration
- learning new development techniques

## Possible learning goals

Through Worldglance development I aim to:

- improve my programming skills
- learn more about interactive 3D graphics
- understand how larger software projects are designed
- improve problem-solving skills
- learn how to turn an idea into a working product
- improve planning and iterative development
- learn from technical failures and design changes

## Evidence

CAS evidence should come naturally from development.

Useful evidence may include:

- screenshots of Worldglance at different stages
- short screen recordings
- screenshots of important GitHub commits or pull requests
- development milestones
- before/after comparisons
- design experiments
- short notes explaining a challenge
- occasional photographs of development work if useful

There is no need to document every commit.

A small number of meaningful pieces of evidence is better than large amounts of repetitive evidence.

## Reflection

Periodic CAS reflections should describe real work.

Useful reflection questions:

- What did I build during this period?
- What changed from my original idea?
- What was difficult?
- How did I solve the problem?
- What did I learn?
- What would I do differently?
- What am I planning next?

Audio reflections may be used.

When preparing a CAS reflection, ChatGPT may help create a natural first-person script based on the actual development that occurred.

The final recording should reflect my genuine experience and be spoken in my own voice.

## Evidence routine

At meaningful milestones:

1. save one or two useful screenshots or recordings
2. note the milestone or challenge
3. keep the relevant GitHub history
4. periodically prepare a short reflection

CAS evidence should remain lightweight and should never become a blocker for development.
