# Worldglance Design Direction

## Overall character

Worldglance should feel:

- modern
- minimal
- smooth
- atmospheric
- calm
- alive
- premium
- readable

It should not feel like a traditional GIS application or a cluttered analytics dashboard.

## Earth appearance

The Earth should be stylized rather than photographic.

Avoid using satellite imagery as the main visual identity.

The visual language may take inspiration from the clarity of modern mapping products and simplified simulation games, but Worldglance should develop its own appearance.

Possible characteristics:

- clean land shapes
- dark or restrained oceans
- controlled color palette
- subtle atmosphere
- clear city lights/activity
- simplified roads
- simplified buildings
- smooth transitions between scales

## Motion

Motion is an important part of the identity.

Animations should feel:

- smooth
- purposeful
- physically understandable
- not excessively fast
- not chaotic

Examples:

- aircraft moving along believable routes
- ships moving through water
- road traffic flowing through cities
- clouds moving gradually
- weather evolving
- event animations appearing clearly without overwhelming the scene

Movement should contribute to the impression of a living planet.

## Camera

Camera behavior must feel excellent.

Important characteristics:

- smooth rotation
- predictable zoom
- no sudden snapping without reason
- comfortable transitions between global and local views
- appropriate movement speed for the current scale
- easy recovery if the user gets disoriented

Camera quality is a core product feature.

## Interface

The interface should remain secondary to the Earth.

Prefer:

- small contextual controls
- clean panels
- progressive disclosure
- clear typography
- restrained use of borders and decoration
- minimal permanent UI

Avoid covering large parts of the globe unless necessary.

## Information

When a user selects something, information should be concise and useful.

Examples:

- location
- object type
- important values
- data freshness
- whether information is observed, modelled or simulated when relevant

## Responsive design

The website should ultimately work well on:

- desktop
- laptop
- tablet
- mobile browser

Desktop development may come first, but architecture should not make later mobile support unnecessarily difficult.

## Design process

Visual design should be evaluated through actual running prototypes.

Do not make important visual decisions only from documentation.

For major visual milestones:

1. build the feature
2. run it
3. inspect it
4. compare it with the intended Worldglance feel
5. adjust it

The design documents describe direction, not pixel-perfect final answers.
